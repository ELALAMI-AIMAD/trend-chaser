How should the 6 new pages share their shell?

The sidebar + topbar exist only in page.tsx today. Picking the right pattern now avoids duplication across all 6 new pages.

A

Shared layout — Recommended

Extract sidebar + topbar into components. A single app/(dashboard)/layout.tsx wraps all pages. Each page is pure content only.

app/
  (dashboard)/
    layout.tsx ← sidebar + topbar live here
    page.tsx          ← dashboard content only
    trends/page.tsx
    calendar/page.tsx
    watchlist/page.tsx
    prompts/page.tsx
    scan-runs/page.tsx
    settings/page.tsx
components/
  app-shell/
    sidebar.tsx
    top-bar.tsx

Pros

  • Change nav once, all pages update
  • Pages stay small & focused
  • Clean RSC boundary

Cons

  • Requires light refactor of existing page.tsx
B

Copy-paste shell — Quick

Keep the existing pattern. Each of the 6 new pages repeats the sidebar + topbar inline, like the current page.tsx.

app/
  page.tsx      ← sidebar + content
  trends/
    page.tsx    ← sidebar + content (copy)
  calendar/
    page.tsx    ← sidebar + content (copy)
  … × 6 pages

⚠ Nav change = edit 7 files

Pros

  • No refactor needed
  • Every page is self-contained

Cons

  • Sidebar duplicated 7×
  • Hard to maintain
C

Layout + strict RSC/client split

Like A, but with an explicit RSC/client boundary. Sidebar is a server component; topbar (Clerk buttons) is a 'use client' island. Most performant, most architectural.

components/app-shell/
  sidebar.tsx       ← Server Component
  top-bar.tsx       ← 'use client' (Clerk, search)
  mobile-nav.tsx   ← 'use client' (toggle)

app/(dashboard)/layout.tsx
  ↳ composes all three above

Pros

  • Optimal bundle splits
  • Clean boundaries, easier to test
  • Production-ready architecture

Cons

  • Most setup work upfront
